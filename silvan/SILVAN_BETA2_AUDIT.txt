2. BUG REPORT

Format per item:  SYMPTOM / WHERE / WHY (so you learn the mechanism) / FIX / TEST

B-01  [BLOCKER] [LIKELY-HIGH]  No OutputPass: image is dark, tone mapping is dead
  SYMPTOM  Terrain reads pure black on slopes (screenshot 2) and near-black red
           at the crater (screenshot 1). Dark green pines. Everything needs
           huge light intensities to be visible.
  WHERE    core/main.js init(): composer has RenderPass + UnrealBloomPass only.
  WHY      Since three r152/r153, tone mapping and the linear->sRGB conversion
           only happen when a material draws straight to the screen. Through
           EffectComposer the scene renders into an off-screen LINEAR buffer,
           and OutputPass is the final step that applies renderer.toneMapping
           and sRGB encoding. Without it, renderer.toneMapping = ACES and
           toneMappingExposure = 1.08 do nothing, and raw linear numbers are
           shown as if they were sRGB.
           [MEASURED] your terrain band colours, as linear values shown raw:
             oceanBed     0x0c131d  ->  ~1/2/3   out of 255
             wetSand      0x2d2b27  ->  ~7/6/5
             lushLowland  0x1a2c1e  ->  ~3/6/3
             slateHighland 0x2f353d ->  ~7/9/12
             peak         0x111317  ->  ~1/2/2
           Those are all black on any monitor.
  FIX      import { OutputPass } from 'three/addons/postprocessing/OutputPass.js';
           composer.addPass(new OutputPass());   // LAST, after bloom
           Then retune once: hemi ~0.5-0.6 (not 1.15), sun 1.0-1.5, bloom
           threshold, fog colour. Tag the grass diffuse CanvasTexture with
           .colorSpace = THREE.SRGBColorSpace (noise textures stay linear).
  TEST     T1 in section 12.

B-02  [BLOCKER] [LIKELY-HIGH]  Grass fails the depth test against terrain
  SYMPTOM  Grass "only shows around certain places". In screenshot 1 the only
           grass visible is the thin red/teal strip along the far ridge,
           where blades are silhouetted against SKY. Nowhere else is grass
           visible, even though the blades exist under the player.
  WHERE    core/main.js: new WebGLRenderer({ logarithmicDepthBuffer: true })
           environment/grass.js: vertex shader ends with plain
           gl_Position = projectionMatrix * viewPosition;
           grep for "logdepthbuf" across the project: zero matches.
  WHY      With a log depth buffer, every built-in material writes a
           re-mapped depth value from its fragment shader. A custom
           ShaderMaterial must include the four logdepthbuf chunks or it
           writes NORMAL depth. Now the buffer holds two different encodings:
           for a point 10 units away, normal depth ~0.99, log depth ~0.33.
           The grass compares its 0.99 against the terrain's 0.33, loses, and
           is discarded wherever terrain is behind it - i.e. almost every
           pixel. It survives only where nothing was drawn behind it: sky gaps
           at ridge lines and crater rims. That reads exactly as "grass only
           around certain places, like the Serpent's Coil".
           The header comments in grass.js record four earlier "grass is
           invisible" fixes (GLSL3 flag, smoothstep undefined behaviour, width
           formula, near-player squash). All real bugs - but this one hides
           behind all of them and was never tested for.
  FIX      Preferred: drop logarithmicDepthBuffer (also fixes B-15), set camera
           near 0.25 / far 1200. Alternative: add logdepthbuf_pars_vertex /
           logdepthbuf_vertex / logdepthbuf_pars_fragment /
           logdepthbuf_fragment chunks to grass.js AND check sky.js (sky,
           clouds, stars), dust.js, rain.js - they are also ShaderMaterials.
  TEST     T2 in section 12.

B-03  [MAJOR] [VERIFIED]  Grass exists only in a 30 x 30 unit window
  SYMPTOM  Even once B-02 is fixed, grass stops ~15 units away and thins out
           well before that: "grass only where the player walks".
  WHERE    environment/grass.js: PATCH_SIZE = 30, BLADE_COUNT 130000 (medium)
  WHY      The sliding-window trick recycles a fixed pool of blades around the
           player. Great for constant cost, but coverage = the pool's size.
           - 130,000 blades / 900 u^2 = 144 blades per u^2. The reference
             GhibliGrass project this was ported from runs ~500 per u^2.
           - The "bald patch" term subtracts up to 2.5 x noise from a blade
             height that averages 0.58 and maxes at 1.16, so past ~half the
             radius many blades get negative height (sink into the ground).
             Real dense radius is closer to 8-10 units, not 15.
           - Far blades shrink to 0.35 scale but never to 0, so the patch edge
             pops in/out as blades wrap.
           - Grass has no biome mask: shoreFade only checks elevation, so it
             also grows on the magma crater and the bare rock highlands
             (that is the red grass in screenshot 1).
  FIX      Section 5 (grass v2): rings + ground-colour trick + biome mask.

B-04  [MAJOR] [VERIFIED]  Grass hue is random: red, magenta, teal
  SYMPTOM  Screenshot 1: crimson/magenta blades with teal tips.
  WHERE    grass.js: vColor = diffuse * color * colorNoise
           core/procedural-textures.js makeSmoothNoiseTexture()
  WHY      The noise texture fills R, G and B with three INDEPENDENT random
           values. The shader multiplies it into the colour, so each region of
           the map is randomly tinted red, green or blue. That texture is
           right for wind/height (wants 3 independent channels) but wrong for
           colour.
  FIX      Colour variation from ONE channel (brightness only) with hue from a
           palette per biome; keep RGB noise only for wind/height sampling.

B-05  [MAJOR] [VERIFIED + derived]  Blade roots do not sit on the drawn ground
  SYMPTOM  On slopes, short blades are buried; some float.
  WHERE    core/procedural-textures.js bakeHeightMapTexture(); grass.js shader
  WHY      Three separate errors stack:
           1. Height texture is 8-bit. [MEASURED] range -1.6..48.9 over 255
              steps = 0.2 units per step.
           2. The shader's manual bilinear samples at floor(uvTexel)/texSize,
              which is a texel BOUNDARY, not a centre (needs +0.5), and then
              the texture also has LinearFilter on top. Result: blurred and
              shifted by about half a texel (~1.6 units). On a 25 degree
              slope that is ~0.7 units of vertical error - bigger than the
              average blade (0.6). [MEASURED] 10.9% of land is steeper than
              25 degrees.
           3. Texel size 3.14 u vs terrain mesh cell 5.33 u: the mesh is
              linear between its vertices while the grass follows a
              different sampling. [MEASURED] mesh vs true height: mean 0.02,
              max 1.8 units (crater rim).
  FIX      One source of truth: bake ONE Float32 (or HalfFloat) heightmap, use
           NearestFilter + texelFetch with correct manual bilinear, and build
           terrain vertices, player height, grass, vegetation placement and
           collision slopes from that same array (section 4).

B-06  [MAJOR] [VERIFIED]  Sun shadow frustum typo
  SYMPTOM  Shadows missing or blocky in large parts of the map.
  WHERE    core/main.js: state.sunLight.shadow.bottom = -d;
  WHY      Property lives on the shadow CAMERA: shadow.camera.bottom. The line
           creates a useless new property, camera.bottom stays at its default
           -5 while left/right/top are +-500. The frustum is 1000 wide but
           only 505 tall, squeezed onto a 1024 x 1024 map: ~1 unit per texel
           horizontally, ~0.5 vertically. Every tree shadow is a 1-unit blob.
  FIX      shadow.camera.bottom = -d; then shadow.camera.updateProjectionMatrix().
           Better: see B-07 (follow the player, small tight frustum).

B-07  [MAJOR] [LIKELY]  Terrain shadows itself: black slopes, acne
  SYMPTOM  Screenshot 2 slope is flat black with no gradient.
  WHERE    environment/terrain.js: castShadow = true AND receiveShadow = true;
           main.js shadow bias -0.0001 with ~1u shadow texels.
  WHY      A surface that both casts and receives shadow at a grazing sun
           angle self-shadows ("shadow acne") when bias is tiny and texels are
           big. Sun sits nearly overhead at noon, low at dusk = acne worst at

  FIX      terrain.castShadow = false (terrain rarely needs to shadow itself;
           fake mountain shade in the terrain shader with slope . sunDir).

B-08  [MAJOR] [VERIFIED + MEASURED]  Pine trees look wrong
  SYMPTOM  Screenshot 2: bare stub of trunk sticking out above every crown;
           tiers like stacked lamp-shades; all pines identical.
  WHERE    environment/forest.js, pine branch of generateFractalForest()
  WHY      (a) TRUNK STUB. Trunk spans the full 16*s height. Top foliage tier
               tops out at ~93.5% of that. [MEASURED] average bare trunk above
               the last tier = 6.5% of trunk height, 1.3-2.2 units on a
               1.5-2.2 scale tree, and the trunk is still ~0.6-0.9*s wide up
               there - a blunt stump, not a tip.
           (b) TIER SHAPES. Tier radius = 0.35*trunkHeight*(1-(j/n)^1.2);
               height = 0.9 * radius. Bottom skirt ~11*s wide on a ~1.5*s
               trunk; top tiers ~1 unit -> there is no crown, so the spike

           (c) SAME MESH EVERYWHERE. One shared cone geometry, jittered once

4. TERRAIN v2: STYLE AND SIZE
--------------------------------------------------------------------------------
4.1 WHERE THE TERRAIN IS NOW  (facts)
    - WORLD_SIZE 800; island radius = 0.45 x 800 = 360 u; land (y >= 4) is
      ~168,000 u^2 = 26% of the world plane. Max height ~49.
    - One mesh, 150 x 150 segments (22,801 verts / 45,000 tris), 5.33 u cells.
    - getElevation() is a live analytic function called from the player, POIs,
      forest, flowers, rocks, lake, heightmap bake.
    - Speed 12 u/s (19 sprint): crossing the island ~60 s walking, ~38 s
      sprinting. 9 POIs = one per ~137 u (11 s of walking).

4.2 SINGLE SOURCE OF TRUTH: BAKE THE HEIGHTMAP ONCE
    - Run getElevation over a grid ONCE, in a Web Worker, into a Float32Array.
      [MEASURED] ~0.39 s per million samples in Node, so 2048 x 2048 (4.2M) is
      ~1.6 s off the main thread. 2048^2 over 1600 u = 0.78 u/texel; memory
      16 MB (Float32) or 8 MB (Half).
    - Export helpers: heightAt(x,z) (correct bilinear), normalAt, slopeAt,
      shoreDistanceAt. EVERYTHING reads these: terrain chunks, grass shader
      (texelFetch, no 8-bit, no half-texel shift), player, collisions,
      vegetation placement, minimap.
    - Also bake a SPLAT/MASK texture (RGBA8): R grass, G rock, B sand/ash,
      A path/trail. Derived from height, slope, distance to crater, distance
      to water, biome noise, POI pads and trails. Grass, trees, flowers,
      rocks all place from this mask. That one texture is what makes the
      world feel authored instead of random.

4.3 CHUNKED TERRAIN (this is what lets the world grow without cost growing)
    - Chunks of 64 x 64 u. Draw radius ~6 chunks (~380 u, matching fog).
    - Four LODs by ring: 65 verts/side (1 u spacing) for the 3x3 around the
      player; 33 (2 u); 17 (4 u); 9 (8 u). Add short vertical "skirts" on
      chunk edges to hide cracks between LODs.
    - [MEASURED budget] ring of 9+16+56+88 chunks = ~79k verts / ~146k tris
      total, versus 22.8k verts / 45k tris today - but the ground around the
      player is 5x sharper (1 u instead of 5.33 u) where you actually look.
    - Per-chunk frustum culling comes free (each chunk is its own mesh).
      Build chunks incrementally (1-2 per frame) as the player moves; reuse
      geometry buffers from a pool.
    - Cost becomes independent of world size: a 3200 u world costs the same
      per frame as an 800 u one. Only memory (heightmap) and bake time grow.

4.4 SURFACE STYLE (what fixes "black wall")
    - Splat shader (onBeforeCompile on MeshStandardMaterial, or small
      custom material): 4-5 layers - sand, grass/moss, dirt/path, rock,
      ash/obsidian - blended by the mask, with slope steering rock in
      automatically (slope > ~35 degrees -> rock).
    - Triplanar sampling of small tiling textures (256-512 px, or purely
      procedural fbm in the shader: zero texture files).
    - Macro variation: low-frequency colour noise across 100-300 u so
      big areas do not look uniform; wet-sand darkening near the waterline;
      warm ash/magma glow ramp near the crater; mossy dark under tree canopy.
    - Ground albedo must already look grassy where grass grows (section 5.2).
    - Decide normals: see 4.7.

4.5 SHAPE (make the land interesting, not just noisy)
    - Use ABSOLUTE frequency octaves (per world unit, not per world size), so
      making the world bigger adds land instead of stretching hills.
      Currently noise frequency is "per WORLD_SIZE": change the world from
      800 to 1600 and every hill doubles in wavelength = mushy.
    - Heights are absolute (24, 90, 40): at 2x width the island will read
      flatter. Scale mountain/crater heights ~1.4x when you widen.
    - Add: ridged noise for the highlands, domain-warp on the coastline
      (coves, headlands), 1-2 river/stream valleys carved from highland to
      sea, a plateau or two for POIs, cliffs on the north/east coast.
    - Remove octaves above ~1 sample per 2 u once the mesh is 1 u spacing
      (no aliasing), and keep everything below the mesh spacing in the
      normal/detail shader instead of in geometry.
    - POI PADS: stamp a flatten-and-blend into the height generator around
      each POI (radius = POI radius + 6, ~8 u falloff), plus a trail mask

5. GRASS v2
--------------------------------------------------------------------------------
5.0 STEP ZERO (10 minutes): fix B-02 and B-04, re-test. Some of your
    "grass missing" complaints disappear immediately. Do not redesign
    before this.

5.1 THE GROUND-COLOUR TRICK (why grass "everywhere" is cheap)
    Real games do not draw blades to the horizon. The ground colour in
    grassy areas is already green-brown with noise; blades add parallax only
    near the camera. Your ground is near-black, so the blade patch edge shows
    up as a hard line. Fix the terrain albedo (4.4) and the edge nearly
    vanishes.

5.2 TWO RINGS
    - NEAR ring (0-25 u): real blades, 5 vertices each (bends smoothly).
      High ~200k, Medium ~120k, Low ~50k blades.
    - MID ring (25-70 u): crossed-card tufts (2 quads, ~8 verts) at 1/10 the
      density but 3-4x larger, same colours, shader fades them in as blades
      fade out. 8-15k tufts.
    - Beyond 70 u: nothing - terrain albedo carries it.

5.3 DENSITY FROM THE MASK (fixes red grass on the crater)
    density = mask.grass * slopeFactor * (1 - mask.path) * clumpNoise
    slopeFactor: 1 below 25 deg, fading to 0 by 40. None on sand, rock, ash.
    Height varies per biome. Player trail can trample (5.6).

5.4 INSTANCING: 10x LESS MEMORY
    Current: every blade is 3 duplicated vertices with 14 floats each.
    [MEASURED] 130k blades = 21.8 MB of GPU buffers. Use
    InstancedBufferGeometry: one 5-vertex blade + per-instance
    (origin.xz, yaw, rand) = 16 bytes per blade = 2.1 MB. Faster to build,
    faster to upload, same look.

5.5 NO POP AT THE EDGE
    Scale blade width AND height to 0 at the ring edge (not 0.35), and remove
    the "bald patch" subtraction that pushes heights negative.

5.6 INTERACTION (cheap, big feel)
    Pass the player position (+ up to 8 NPC/animal positions) as a uniform
    array; blades within ~1.5 u bend away and spring back. Also gives you a
    visible trail for free.

5.7 QUALITY AND LIVE REBUILD
    Tier controls ring radius and density; rebuild in place when the player
    changes tier (today: "applies on reload"). Never draw grass on top of
    POI pads or under building footprints (mask).

5.8 ACCEPTANCE
    - From spawn, looking across flat lowland: continuous grass to ~25 u, then
      tufts to ~70 u, then grassy ground colour, no visible ring.
    - Crater, beach, rock highlands: zero grass.
    - Same look at noon and dusk (colours in linear, tinted by sun).
    - Grass cost <= 1.5 ms GPU on the Medium tier at 1080p.

6.2 PINE SPEC (fixes B-08)

      and is hidden inside the crown above ~55% H. Crown top = trunk top
      + 0.05 H so no stump is possible.

      use a seeded jitter PER VARIANT.
    - 3 shapes: tall/narrow, squat/wide, sparse/half-dead (near the crater

    - Vertex colour: darker at the base of each tier, lighter at the tips

      shadow for depth.
    - Wind: tree-wide bend in WORLD space: offset = windDir x h^2 x amp,
      where h = height / H (a per-vertex attribute), applied AFTER the
      instance transform so the whole tree moves as one.
    - Trunk collision radius from the real trunk radius, not 0.7*s + 0.6.

6.3 PLACEMENT RULES (fixes B-09), from the mask
      species     elevation      slope     notes

8.1 TARGETS

8.2 WHAT COSTS THE MOST TODAY (order of payoff)
    1. Tree trunks ~3.5M tris, drawn twice with shadows     (B-24)   ~ 10x win
    2. logarithmicDepthBuffer disables early-Z              (B-15)
    3. Shadow map: 1000-unit frustum, terrain casts         (B-06/07)
    4. Rocks ~300k tris, no LOD                             (B-22)
    5. Grass 21.8 MB buffers + a full-screen-ish overdraw   (5.4)
    6. Always-on rain 45k + fireflies 1.2k + dust 3.5k      (B-25)
    7. Bloom at half res is fine; keep, but tier-gate it
    NOTE: I could not run a GPU profile. Measure #1-3 first with T5 (section
    12) before assuming the order.

8.3 QUALITY TIERS - EXTEND settings.js BEYOND bladeCount
    Every tier controls:
      pixel ratio / resolution scale (0.67, 0.85, 1.0, 1.25)
      shadow map size (off / 1024 / 2048) and radius (60 / 100 / 120 u)
      grass ring radius + density
      tree LOD distances, flower/rock draw distance
      rain particles (8k / 20k / 45k), fireflies, dust
      bloom (off / half-res / half-res), AA (off / SMAA / MSAA 4)
    Change tiers LIVE (rebuild the affected system) - no reload.

8.4 ADAPTIVE RESOLUTION (best perf feature per line of code)
    Keep a rolling average of the last 60 frame times. If avg > 20 ms for 2 s,
    drop resolution scale one step (min 0.6); if avg < 12 ms for 5 s and
    headroom exists, raise one step. With the chunky-low-res art direction
    (4.7 B) players will not notice.

      POI's static meshes into 1-3 draw calls (Warm Paw fence/benches etc.).
    - Point lights: you already cull POI lights by distance - good. Cap

    - Dispose geometry/material/texture when chunks unload.

13.3 GLOSSARY (the terms used above)
    OutputPass      final post-processing step: tone mapping + sRGB encoding.
    Linear vs sRGB  lighting maths is done in linear light; screens expect
                    sRGB. Skip the conversion and everything looks too dark.
    Log depth       alternative depth encoding; every shader must write it,
                    custom shaders must opt in or their depth is wrong.
    Draw call       one "draw this mesh" order to the GPU; fewer is cheaper.
    Instancing      draw one mesh N times with per-copy data in one call.
    LOD             level of detail: cheaper model farther away.
    Chunk           a fixed-size tile of world built/streamed on demand.
    Splat map       texture whose channels say how much of each ground type
                    (grass, rock, sand...) is at each spot.
    Triplanar       texturing by projecting from x/y/z so steep slopes do not
                    stretch.
    Shadow acne     speckled self-shadowing from depth precision; fix with
                    bias/normalBias and higher shadow resolution.
    Impostor        a flat camera-facing picture standing in for a far model.
    Early-Z         GPU skips shading pixels that are hidden; writing custom
                    depth turns this off.
